1.5 · MMAC 矩阵乘加 ​

向量加法让每个 lane 各算一个元素。矩阵乘加则让一个 wave 的多个 lane 协作，按照一条矩阵指令的约定计算一个输出块。

先认识这几个词

MMAC（Matrix Multiply-Accumulate）指矩阵乘加。Tile 是从大矩阵里切出的一小块。累加器保存已经算好的部分和，下一段计算可在它上面接着加。

输出块的列数 有 列
每个输出累加的乘积项数 有 列， 有 行

16×16×16 会更新一个 16×16 的输出块，每个输出累加 16 个乘积。通常把一次乘加计作 2 FLOPs，这条指令的数学工作量就是 2 × 16 × 16 × 16 = 8192 FLOPs。一个更大的 GEMM（通用矩阵乘法）需要许多这样的块， 方向还会分段累加。

2. 一个 wave 怎样合起来算 ​

普通 VALU（向量算术逻辑单元） 的乘加可以由各 lane 按自己的操作数计算。执行 MMAC 时，一个 wave 共同计算一个矩阵块，每个 lane 按指令规定持有 A、B 和累加结果的一部分。需要匹配精度和 lane 到矩阵元素的布局。换一种指令形状或目标架构，对应关系也可能变。

矩阵形状和操作数布局都要匹配

同一块矩阵数据放在不同的 lane 或寄存器位置，指令读取到的片段就会不同。应按目标 ISA 组织数据，必要时先通过 LDS 布局或寄存器交换做重排。

BW100 的 E07 从 HIP 内置函数 __builtin_hcu_mmac_f32_16x16x16_f16 生成了这条指令：

asm
v_mmac_f32_16x16x16_f16 v[1:4], v[5:6], v[7:8], v[1:4]

本例每个 lane 提供两组 FP16 输入片段，分别从 v[5:6] 和 v[7:8] 读取。每组两个 32 位 VGPR 可存四个 FP16 值。v[1:4] 保存四个 FP32 值，既作为输入 C 也接收输出 D。整个 wave 的 64 个 lane 合起来得到 16×16 输出。具体哪一 lane 对应哪几个矩阵元素，以目标指令的布局为准。E07 的源码、ISA 和测量口径

3. 从读取 Tile 到写回结果 ​

在一种常见的分块实现中，全局内存中的 A、B tile 读入后，可按需要经过 LDS 共享，再把指令需要的片段送入寄存器。MMAC 把这一段的计算积到结果寄存器里。处理完 方向的各段后，Kernel 才写回输出块。用流水线时，可以提前加载下一段，在当前已就绪的片段上继续计算。

要确认是否使用了矩阵指令，可以从 HIP 内置函数或 Triton 的 tl.dot 追到导出的 .s。查看实际生成的指令、输入与累加类型、资源用量。不同 DCU 目标支持的形状和指令语义应分别核对。

4. 怎样读延迟和吞吐 ​

  • 依赖延迟看同一个累加结果多久后可被下一条指令使用。E07 在这条依赖链上测得约 10.01 clock64 tick/指令，包含实验测量开销。
  • 稳态吞吐看独立工作足够多时，单位时间能完成多少运算。E07 用八条独立累加链，测得这条指令约 333.49 TFLOPS。
  • 算子性能还受 tile 的加载、布局重排、驻留条件和写回影响。E09 测的是完整 GEMM，使用各配置的独立计时和 PMC。E07 指令微基准 · E09 GEMM

5. 动手实战 · 在汇编里找到矩阵乘加 ​

从仓库根目录运行。这个例子需要支持该内置函数的 BW100 和 DTK。先让编译器保留设备汇编，再运行 E07 测试。

bash
cd experiments
hipcc -O3 -std=c++17 --offload-arch=gfx936 -save-temps 08_mmac_builtin_bench.hip -o 08_mmac_builtin_bench
grep -m 1 'v_mmac_f32_16x16x16_f16' *mmac*-hip-amdgcn-*-gfx936.s
./08_mmac_builtin_bench

第一处匹配在本次实测中是下面这一行。没有设备时，可以用这行完成同样的读指令练习。

asm
v_mmac_f32_16x16x16_f16 v[17:20], v[33:34], v[35:36], v[17:20]

先读指令名里的 16x16x16，分别找出 M、N 和 K。接着找出 A、B 和部分和。两个输入占 v[33:34]、v[35:36]，这条指令读写同一组部分和 v[17:20]。寄存器编号由编译器分配。程序最后输出的两项 MMAC 数值分别用来观察吞吐和依赖延迟，本次 BW100 复测约为 333.5 TFLOPS 和 10.0 tick/指令。E07 实验源码与计时方法
