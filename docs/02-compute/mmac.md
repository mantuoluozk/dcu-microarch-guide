# 1.5 · MMAC 矩阵乘加

向量加法让每个 lane 各算一个元素。矩阵乘加则让一个 wave 的多个 lane 协作，按照一条矩阵指令的约定计算一个输出块。

::: info 先认识这几个词

**MMAC**（Matrix Multiply-Accumulate）指矩阵乘加。**Tile** 是从大矩阵里切出的一小块。**累加器**保存已经算好的部分和，下一段计算可在它上面接着加。

:::

## 1. 指令形状里的 M、N、K

一条矩阵乘加指令可写成 $D = A \times B + C$。用 $M \times N \times K$ 描述它处理的形状：

| 字母 | 代表什么 | 数组形状 |
|---|---|---|
| $M$ | 输出块的行数 | $A$ 有 $M$ 行 |
| $N$ | 输出块的列数 | $B$ 有 $N$ 列 |
| $K$ | 每个输出累加的乘积项数 | $A$ 有 $K$ 列，$B$ 有 $K$ 行 |

`16×16×16` 会更新一个 `16×16` 的输出块，每个输出累加 16 个乘积。通常把一次乘加计作 2 FLOPs，这条指令的数学工作量就是 `2 × 16 × 16 × 16 = 8192 FLOPs`。一个更大的 GEMM（通用矩阵乘法）需要许多这样的块，$K$ 方向还会分段累加。

## 2. 一个 wave 怎样合起来算

普通 **VALU**（向量算术逻辑单元） 的乘加可以由各 lane 按自己的操作数计算。执行 MMAC 时，一个 wave 共同计算一个矩阵块，每个 lane 按指令规定持有 A、B 和累加结果的一部分。需要匹配精度和 **lane 到矩阵元素的布局**。换一种指令形状或目标架构，对应关系也可能变。

::: tip 矩阵形状和操作数布局都要匹配

同一块矩阵数据放在不同的 lane 或寄存器位置，指令读取到的片段就会不同。应按目标 ISA 组织数据，必要时先通过 LDS 布局或寄存器交换做重排。

:::

BW100 的 E07 从 HIP 内置函数 `__builtin_hcu_mmac_f32_16x16x16_f16` 生成了这条指令：

```asm
v_mmac_f32_16x16x16_f16 v[1:4], v[5:6], v[7:8], v[1:4]
```

本例每个 lane 提供两组 FP16 输入片段，分别从 `v[5:6]` 和 `v[7:8]` 读取。每组两个 32 位 VGPR 可存四个 FP16 值。`v[1:4]` 保存四个 FP32 值，既作为输入 C 也接收输出 D。整个 wave 的 64 个 lane 合起来得到 `16×16` 输出。具体哪一 lane 对应哪几个矩阵元素，以目标指令的布局为准。[E07 的源码、ISA 和测量口径](../labs/lab09-mmac-builtin-and-valu.md)

## 3. 从读取 Tile 到写回结果

在一种常见的分块实现中，全局内存中的 A、B tile 读入后，可按需要经过 LDS 共享，再把指令需要的片段送入寄存器。MMAC 把这一段的计算积到结果寄存器里。处理完 $K$ 方向的各段后，Kernel 才写回输出块。用流水线时，可以提前加载下一段，在当前已就绪的片段上继续计算。

要确认是否使用了矩阵指令，可以从 HIP 内置函数或 Triton 的 `tl.dot` 追到导出的 `.s`。查看**实际生成的指令、输入与累加类型、资源用量**。不同 DCU 目标支持的形状和指令语义应分别核对。

## 4. 怎样读延迟和吞吐

- **依赖延迟**看同一个累加结果多久后可被下一条指令使用。E07 在这条依赖链上测得约 **10.01 clock64 tick/指令**，包含实验测量开销。
- **稳态吞吐**看独立工作足够多时，单位时间能完成多少运算。E07 用八条独立累加链，测得这条指令约 **333.49 TFLOPS**。
- **算子性能**还受 tile 的加载、布局重排、驻留条件和写回影响。E09 测的是完整 GEMM，使用各配置的独立计时和 PMC。[E07 指令微基准](../labs/lab09-mmac-builtin-and-valu.md) · [E09 GEMM](../labs/lab07-triton-gemm-vs-rocblas.md)

## 5. 思考题

同一个 `16×16` 输出块的归约长度变为 **32**。如果沿 $K$ 拆成两段，连续使用两条 `16×16×16` 的 MMAC，数学工作量是多少？在 E07 所用指令里，两段之间的部分和用什么精度保存？

::: details 查看答案

两段各做 `2 × 16 × 16 × 16 = 8192 FLOPs`，合计 **16384 FLOPs**。在这条指令中，两个输入片段用 FP16，累加片段用 **FP32**。第一段留下的 FP32 结果可作为第二段的累加输入。

:::
